외부 API 연동 4건

#1필터 검색이 느림 — 외부 API를 끝까지 전부 호출하고 있었다연구자 포털 · 논문 검색›
증상
국내·해외 구분 같은 필터를 걸고 검색하면 첫 페이지가 뜨기까지 오래 걸림
원인
외부 검색 API에는 해당 필터가 없어, 결과를 받아 서버에서 거르는 구조. 첫 페이지 10건을 보여 주려고 원본 결과가 바닥날 때까지 모든 페이지를 호출하고 있었음
해결
  • 요청한 페이지를 채울 만큼(페이지 번호 × 페이지 크기)만 가져오고 멈춤
  • 한 요청에서 외부 호출은 최대 5회로 제한
  • 전체 건수는 "최소 이만큼 더 있다"로 추정해 다음 페이지 버튼 유지
  • 받아 온 결과는 캐시에 두고 다음 페이지에서 이어서 사용
결과
필터 검색 조회 속도 단축. 외부 API 호출량이 결과 수와 무관하게 상한을 가짐
배운 점
외부 API 뒤에서 후처리할 때는 "정확한 전체 건수"보다 "지금 화면에 필요한 만큼"을 기준으로 설계해야 한다.
#2띄어쓰기가 있는 검색어만 결과가 이상함 — URLEncoder의 '+'연구자 포털 · 논문 검색›
증상
여러 단어로 된 검색어에서 결과가 기대와 다르고, 여러 페이지를 넘기다 외부 서버 500 오류가 나면 이미 받은 결과까지 전부 실패 처리
원인
Java URLEncoder는 HTML 폼 규칙이라 공백을 +로 바꿈. 외부 API는 쿼리 파라미터의 공백을 %20으로 기대
해결
  • 인코딩 뒤 +를 %20으로 치환
  • 페이지를 이어 받는 중 500이 나면, 이미 모은 결과가 있을 때는 부분 결과로 응답하고 로그에 기록
URLEncoder.encode(v, UTF_8).replace("+", "%20")
결과
여러 단어 검색 정상화. 외부 서버 일시 오류에도 화면이 비지 않음
배운 점
"인코딩했다"로 끝내지 말고, 상대 서버가 어떤 인코딩 규칙을 기대하는지까지 맞춰야 한다.
#3"토큰 발급 실패"만 찍히는 오류 — 원인을 볼 수 있게 만들기연구자 포털 · 외부 API 인증›
증상
운영 중 간헐적으로 검색이 실패하고 로그에는 "토큰 발급에 실패했습니다"만 남음
원인
응답이 JSON이 아닐 때는 파싱 예외로, JSON일 때는 고정 문구로만 실패를 던져 외부 서버가 준 오류 코드·메시지를 버리고 있었음
해결
  • JSON이 아닌 응답은 원문 일부를 담아 별도 예외로
  • 응답의 errorCode · message · statusCode를 모아 예외 메시지에 포함
  • 로그에서 토큰 · 계정 · MAC 주소는 ***로 마스킹
결과
실패 원인을 외부 응답 코드로 바로 구분 가능. 민감정보는 로그에 남지 않음
배운 점
재현이 어려운 장애는 고치기 전에 "다음에 나면 원인이 보이게" 만드는 것부터. 단, 로그에 비밀 값이 새지 않게.
#4해외 논문 상세가 안 열림 — 외부 응답 지연에 대비한 대체 화면연구자 포털 · 상세 조회›
증상
일부 해외 논문은 상세 조회 API가 응답하지 않거나 실패해 상세 화면 자체가 열리지 않음 → 원문 신청도 불가
원인
상세 조회가 외부 API 한 번에 전적으로 의존. 타임아웃 기준도 없어 느린 응답에 그대로 묶임
해결
  • 연결 10초 · 응답 15초 타임아웃, 1회 재시도
  • 실패하면 검색 단계에서 캐시해 둔 기본 정보로 상세 화면 구성
  • 상세 응답에 빠진 필드는 캐시 값으로 보완, 화면에 "상세 조회 불가" 안내
결과
외부 상세 API가 실패해도 기본 정보 확인과 원문 신청이 가능
배운 점
외부 API 실패는 "에러 페이지"가 아니라 "덜 풍부한 정상 화면"으로 처리할 수 있다.

#5AI 검색용 텍스트 저장 실패 — 문자열 연결의 4,000바이트 한도협업 시스템 · 연구자 검색›
증상
연구자 정보(소속·학력·논문·과제·초록 등)를 합쳐 검색용 텍스트 컬럼에 저장하는 UPDATE가 일부 연구자에서 실패
원인
CLOB 컬럼을 각각 4,000자로 잘라 ||로 이었는데, 연결 결과가 VARCHAR2로 계산돼 SQL의 4,000바이트 한도를 넘음. 내용이 많은 연구자에서만 발생
해결
  • 각 조각을 TO_CLOB()으로 감싸 연결 자체를 CLOB 연산으로
  • 필드별로 1,000자씩 잘라 한쪽 필드가 독점하지 않게 하고, 최종 결과를 4,000자로 제한
결과
모든 연구자의 검색 텍스트 저장 정상화
배운 점
데이터가 많은 일부 행에서만 나는 오류는 타입 한도를 먼저 의심한다. 연결 연산의 결과 타입은 피연산자가 정한다.
#6경력 여러 건 저장 시 일련번호 중복 — INSERT ALL과 시퀀스협업 시스템 · 연구자 프로필›
증상
학력·경력을 여러 건 한 번에 저장하면 같은 일련번호가 들어가 저장이 실패
원인
INSERT ALL … SELECT 1 FROM DUAL로 여러 행을 넣으면서 시퀀스.NEXTVAL을 썼는데, INSERT ALL에서는 원본 행 하나당 NEXTVAL이 한 번만 평가돼 모든 행이 같은 값을 받음
해결
  • 서비스 계층에서 목록을 돌며 한 행씩 INSERT
  • 목록 길이가 달라도 안전하게 인덱스 범위 확인
결과
여러 건 저장 시 행마다 고유 일련번호 부여
배운 점
한 문장으로 여러 행을 넣는 최적화는 시퀀스 · 트리거 같은 "행마다 달라야 하는 값"과 충돌할 수 있다.

#8한국어 Windows에서만 플러그인이 안 뜸 — SDK의 인코딩 미지정Synapse 플러그인›
증상
config.yaml에 한글 설명을 넣자 플러그인 탐색 단계에서 UnicodeDecodeError
원인
synapse-sdk가 config.yaml을 path.open()으로 인코딩 없이 열어, 한국어 Windows에서는 시스템 기본값 cp949로 읽음 (UTF-8 파일과 불일치)
해결
  • config.yaml은 ASCII로만 작성하고 README에 원인과 재현 조건 기록
  • SDK에서 encoding="utf-8"을 지정하면 근본 해결
  • CI에 Windows 러너를 추가해 OS별 문제를 함께 확인
결과
Ubuntu · Windows 양쪽에서 테스트 통과
배운 점
파일을 열 때 인코딩을 생략하면 "내 PC에서는 되는" 코드가 된다. OS 차이는 CI 매트릭스로 미리 잡는다.
#9JS로 옮긴 청크 로직이 1건만 다름 — strip 경로 차이포트폴리오 데모›
증상
위 데모용으로 chunk_text()를 JavaScript로 옮긴 뒤 Python 원본과 15개 조건으로 비교했더니 1건 불일치 (청크 앞에 공백 한 칸)
원인
overlap이 0이고 조각이 공백으로 시작할 때, Python은 f"{tail} {piece}".strip()을 거치지만 JS는 다른 분기로 빠져 trim()을 건너뜀
해결
분기 조건을 원본과 같게 맞춤. Python 출력을 JSON으로 저장하고 Node에서 같은 입력을 돌려 비교하는 검증 스크립트 작성
결과
15 / 15 일치
배운 점
C# → Python 때와 같다. 옮긴 코드는 "비슷해 보이는지"가 아니라 같은 입력에 같은 출력이 나오는지로 확인한다.
