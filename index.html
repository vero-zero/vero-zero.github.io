PROJECT 01 · 개인 프로젝트

Paper RAG Dataset — Synapse 플러그인

2026.11

데이터메이커가 공개한 synapse-sdk로 오픈액세스 논문을 수집해 RAG용 청크 데이터셋과 데이터 품질 리포트를 만드는 플러그인입니다. AI 코딩 에이전트(Claude Code)와 함께 개발했습니다.

synapse-sdk v2Python 3.12Pydantic v2httpxpytestrespxOpenAlex API

문제

  • 논문 초록은 길이가 제각각이라 그대로는 검색 품질이 들쭉날쭉
  • 청크 경계에서 문맥이 끊기고, 어떤 논문의 조각인지 알 수 없음
  • 몇 건이 왜 빠졌는지 모르면 데이터셋을 믿기 어려움

접근

  • 문장 경계를 지키며 자르고, 앞 청크 끝을 겹침(overlap)
  • 제목을 본문 앞에 붙여 청크 하나만으로도 출처를 알 수 있게
  • DOI(없으면 정규화 제목)로 중복 제거, 제외 사유를 manifest와 Synapse 메트릭으로 기록

결과

  • 영어 논문 30편 → 청크 94개, 한국어 20편 → 35개
  • 로직을 플랫폼과 분리해 단위 테스트, SDK LocalExecutor로 통합 테스트 (19개)
  • SDK가 config.yaml을 시스템 인코딩으로 읽어 한국어 Windows에서 실패하는 문제를 발견해 원인 기록

PROJECT 02 · 실무

연구자 포털 해외 원문복사 서비스 연동

2026.03 ~ 현재

국가 연구기관 연구자들이 쓰는 포털에서, 따로 이용하던 해외 원문복사 서비스(RapidILL)를 바로 쓸 수 있도록 논문 검색부터 원문 신청까지 연동했습니다. 개발과 운영을 맡고 있습니다.

Java 17Spring 5.3전자정부프레임워크 4.3MyBatisOracleRESTSOAP · JAXB

문제

  • 연구자가 논문 검색과 원문 신청을 서로 다른 서비스에서 따로 처리
  • 외부 API 두 개(REST, SOAP)에 의존해 장애 지점이 늘어남

접근

  • ScienceON REST로 포털 안에서 검색하고, 결과에서 바로 RapidILL SOAP 신청
  • 신청·반려·실패·재작성 상태 흐름과 상태별 메신저 알림
  • 관리자 권한 체계, 문서뷰어 연동(프록시로 도메인 노출 방지)

운영에서 배운 것

  • 요청·응답 로그를 남겨 토큰 오류 원인 추적
  • 상세 조회가 실패해도 기본 정보는 보이도록 처리
  • 검색 후처리 방식을 바꿔 조회 속도 개선

회사 소스는 공개하지 않습니다. 구조와 흐름만 정리했습니다.

PythonDjangoMySQLJavaScriptUbuntuGunicorn

AI와 일하는 방식

실무에서는 Claude Code를, 새 기술을 익힐 때는 ChatGPT·Gemini·Claude Cowork를 함께 씁니다.

1

맡길 범위를 먼저 정합니다

운영 DB에는 읽기 전용 조회 스크립트만 연결해 에이전트가 데이터를 직접 확인하며 원인을 분석하게 합니다.

2

되돌릴 수 없는 작업엔 안전장치

DDL처럼 되돌리기 어려운 작업은 백업 후 개발 DB에서 검증한 뒤 운영에 반영하도록 절차를 정했습니다.

3

설계와 검증은 제가 합니다

Synapse 플러그인도 설계와 검증 기준은 제가 정하고, 구현과 테스트는 에이전트와 나눠 진행했습니다.
